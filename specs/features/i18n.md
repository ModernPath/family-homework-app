# Feature: Locale (English / Finnish)

## Problem Statement

The kitchen tablet is used in Finnish-speaking households and by English speakers. Hardcoded English chrome (nav, setup, dates, errors) forces parents to translate labels for children. PRD OD-6 is resolved: both languages, browser autodetection, user-selectable `en` / `fi` persisted with the household.

## Proposed Change

UI chrome, validation errors, and date headings follow `household.settings.locale` (`en` | `fi`). New households pick locale from `navigator.languages` (Finnish → `fi`, otherwise `en`). A language switcher in the main nav (`EN` | `FI`) updates locale immediately and persists it. `<html lang>` matches the active locale. Backup import normalizes unknown locale values to `en`.

## Acceptance Criteria

### AC1: Browser autodetection on first launch
**Given** no household exists yet and `navigator.languages` is `["fi-FI", "en"]`  
**When** `createEmptyHousehold()` runs  
**Then** `settings.locale === "fi"`

### AC2: Non-Finnish browsers default to English
**Given** no household exists yet and `navigator.languages` is `["en-US"]`  
**When** `createEmptyHousehold()` runs  
**Then** `settings.locale === "en"`

### AC3: Language switcher in main nav
**Given** the household locale is `en` and AppShell is visible  
**When** the user taps the `FI` button in the language group  
**Then** `household.settings.locale === "fi"`, nav links read `Tänään`, `Viikko`, `Asetukset`, and `document.documentElement.lang === "fi"`

### AC4: English nav after switching back
**Given** the household locale is `fi`  
**When** the user taps the `EN` button  
**Then** nav links read `Today`, `Week`, `Setup` and `document.documentElement.lang === "en"`

### AC5: English today heading
**Given** locale is `en` and local date is 2026-09-02  
**When** `formatTodayHeading("en", date)` runs  
**Then** the string is exactly `Wednesday, Sep 2`

### AC6: Finnish today heading
**Given** locale is `fi` and local date is 2026-09-02  
**When** `formatTodayHeading("fi", date)` runs  
**Then** the string is exactly `keskiviikkona 2.9.`

### AC7: Finnish week column
**Given** locale is `fi` and date string `2026-09-02`  
**When** `formatWeekColumn("fi", "2026-09-02")` runs  
**Then** the string is exactly `Ke 2.9.`

### AC8: Domain errors shown in active locale
**Given** locale is `fi` and the user submits a blank member name  
**When** the Members form shows the validation error  
**Then** the visible text is exactly `Nimi on pakollinen`

### AC9: Import normalizes unknown locale
**Given** a backup JSON whose `settings.locale` is `"sv"`  
**When** `parseBackup` runs  
**Then** the returned household has `settings.locale === "en"`

### AC10: Remaining chrome uses translation keys
**Given** locale is `fi`  
**When** AppShell, ColorSwatches, and EmojiPicker render  
**Then** main nav `aria-label` is `Päävalikko`, color radiogroup name is `Väri`, and icon listbox name is `Valitse kuvake`

## Risk

- What could break: UI tests that query English chrome if jsdom inherits a Finnish `navigator.language`; date assertions that assumed a single `en-US` format.
- Rollback: remove `LanguageSwitcher`, keep English catalogs only, restore `html lang="en"`.
